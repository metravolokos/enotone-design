# enoTone MVP — решение о смене приоритетов (2026-11-04)

## Цель и критерий результата
Цель — два реально работающих музыкальных приложения **enoTone**: Windows 11 (EXE/portable) и Android (APK, Huawei без Google Play Services), воспроизводящие FLAC из Cloud Mail.ru WebDAV **/AllMusic**. Требуются вход в облако, список композиций/альбомов/исполнителей, обложки, выбор трека, Play/Pause/Stop, Seek и переключение композиций; Android — фоновое воспроизведение и системная Media3 media session с полноценным медиа-управлением. Внешний вид — обычный современный музыкальный плеер, с использованием утверждённых ресурсов enoTone по мере их фактической доступности.

**Сборка и зелёные тесты не равны пользовательской приёмке.** Готовность подтверждается запуском EXE и APK, реальным воспроизведением и проверкой владельцем на целевых устройствах. Непроверенное обозначать непроверенным.

## Архитектурное решение
Сохраняем модульную архитектуру и существующие исходники. Для PoC проверяем переход с собственного проблемного libcurl/OpenSSL-тракта на платформенные HTTPS-решения: Windows — Qt Network / QNetworkAccessManager + Qt Multimedia; Android — системное доверие TLS/HTTP (предпочтительно OkHttp) + Media3/ExoPlayer. Это **целевая гипотеза для короткой интеграционной проверки**, не заявление о готовой реализации. Проверить реальную авторизацию Cloud Mail.ru, Range/206, Content-Range, отмену, Seek и совместимость с аудиодвижком. Если конкретный выбор не работает — документировать причину и выбрать минимальную платформенную альтернативу, не создавать ещё один универсальный транспорт.

Core остаётся независимой общей библиотекой каталога, метаданных и обложек; его интеграция не должна блокировать первый работающий звук. Проверенные части переносить/подключать по необходимости с фиксацией происхождения и лицензий. Дизайн — отдельный источник утверждённых ресурсов, не блокер базового функционального UI.

## Приоритеты и запреты на разрастание
1. Зафиксировать последние **фактически** рабочие коммиты, EXE/APK и подтверждённые сценарии.
2. Два небольших независимых задания по транспорту и воспроизведению Windows/Android.
3. Подключить медиатеку/обложки и стандартные экраны.
4. Выпустить и принять оба приложения, затем исправлять конкретные дефекты и добавлять функции.

До первого MVP не начинать без отдельного решения: универсальный сетевой стек, новые схемы кэша, многочасовые стресс-тесты, большие рефакторинги, новую систему координации. Короткие регрессионные тесты обязательны для изменённого поведения; долгие испытания — только при доказанном риске.

## Организация
Владелец утверждает продукт и принимает сборки. Чат интеграции задаёт общие приоритеты; профильные чаты PoC, Core и design отвечают за свои области. Локальные агенты DeepSeek Harness — основные исполнители (один Windows, один Android, третий по мере необходимости для интеграции); Codex Cloud — выборочно при оправданной стоимости. Один агент — одна ограниченная задача/ветка/PR; без параллельного редактирования общих файлов. Состояние, ограничения, тесты и ссылки на артефакты фиксируются в GitHub. Чаты не синхронизируются автоматически.

## История и публикация
**Полную историю сохраняем:** не удалять и не переписывать Git-коммиты, PR, Issues и обоснования решений в трёх существующих репозиториях. Разработку MVP пока ведём здесь. **Новый продуктовый репозиторий `metravolokos/enotone` сейчас НЕ создавать**: после приёмки двух приложений допускается публикация чистого снимка исходников с новой Git-историей, README, сборками и документацией происхождения кода; старые репозитории останутся архивом разработки. Решение о публичности/приватности старых репозиториев принимается отдельно с учётом GitHub Actions, зависимостей и лицензий. Ни один репозиторий не переводить в private/archived автоматически.

## Отчётность
Для каждого PR: что изменено, что действительно проверено, что не проверено, ссылки на сборки, блокеры и следующий минимальный шаг. Изменение архитектуры или расширение объёма требует отдельного согласования.

## Роль этого репозитория — Design
Сохранять утверждённые логотип, маскота, палитру, иконки и визуальные решения без самовольной замены. Приоритет — доступный разработчикам минимальный набор ресурсов и практические экраны Windows/Android (медиатека, альбом, исполнитель, Now Playing), с явным статусом утверждения каждого ресурса. Не блокировать функциональный MVP отсутствующими декоративными элементами. Не считать материалы, находящиеся только в Library/чатах, уже опубликованными в GitHub.
