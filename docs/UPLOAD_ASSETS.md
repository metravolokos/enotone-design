# Перенос утверждённых графических ресурсов

**Состояние:** 12 исходных PNG/JPG сохранены в GitHub без изменений в составе проверяемого архива, разбитого на 5 двоичных частей. Не требуется вручную загружать изображения с изменением формата или качества.

## Как восстановить после клонирования

Из корня репозитория:

```bash
python tools/restore_assets.py
```

Только стандартная библиотека Python. Скрипт соединяет `assets/packages/approved-assets.zip.part01`…`part05` в памяти, сверяет SHA-256 и CRC, распаковывает содержимое на исходные пути и проверяет контрольные суммы утверждённых оригиналов.

## Что восстанавливается

- `assets/references/bandit-10-approved.png` — исходный выбранный коллаж 10 сцен Бандита;
- `assets/references/ui-palette-approved.jpg` — утверждённая палитра;
- `assets/icons/originals/four-icon-board.png` — четыре принятые иконки;
- `assets/icons/exports/` — восемь PNG (432 и 512 px);
- `assets/icons/preview/icon-review.png` — обзор.

Оригинальная доска иконок и палитра доступны напрямую в GitHub. Коллаж Бандита дополнительно сохранён как два бинарных фрагмента в `assets/references/source-parts/`, что позволяет восстановить его независимо от ZIP.

### Контроль целостности

Архив ZIP: `d1ff1752b73d468e8b063e715b464d19f76d69e84d180e65dd0c9230f21393c1` (SHA-256).

Список SHA-256 отдельных файлов — `docs/SOURCES.sha256`.

Все части должны оставаться без изменений. При следующем обновлении дизайн-проекта можно перенести большие файлы отдельными Git LFS-объектами либо прямой загрузкой, сохраняя их байтовое содержимое.

**Не перегенерировать Бандита и не изменять его пропорции. Рабочие проекты AllMusic не затрагивать.**
